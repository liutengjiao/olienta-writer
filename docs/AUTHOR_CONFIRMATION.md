# 作者确认记录

Olienta 采用“保存即确认”的原则。

## 规则

- 每章正文保存为 `manuscript/chapters/*.md` 后，即视为作者确认。
- 确认记录从本地 Markdown 正文文件自动生成，不需要额外按钮。
- 只有有正文内容的章节会进入确认记录；只有标题的空章节和“正文待写”这类占位正文不会计入。
- 「作者确认」页显示章节号、标题、字数、正文文件路径和摘要。
- 正文保存后会写入 `chapter_confirmation_chain_updated` 任务记录，说明正文、事实库和作者确认记录已经完成同步。
- 如果正文来自候选稿采用，系统还会写入 `logs/confirmations/{章节号}.md`，记录候选稿路径、正文路径、采用方式和 AI 必须遵守的确认规则。
- 候选稿采用会写入 `candidate_adopted` 和 `candidate_confirmation_summary_written` 任务记录。

## AI 约束

整章生成提示词会包含“已确认正文记录”。AI 必须服从这些记录，不能改写、反驳、覆盖或制造对立。

## 专注写作

因为作者拥有对每一个字的最终修改和确认权，正文写作必须提供专注模式。

- 专注模式只保留当前章节正文编辑器、章节位置、保存状态和退出入口。
- 全局导航、项目结构栏、右侧 Agent 和底部任务栏在专注模式中隐藏，避免干扰作者逐字修改。
- 专注模式不改变确认规则：正文仍然只有在作者保存后，才进入作者确认记录。
- AI 候选稿、蓝图和建议不能在专注模式中自动覆盖正文。

## 边界

系统记录章节摘要、文件路径和候选稿采用确认摘要，并同步生成 `facts/author-confirmation.md`。
