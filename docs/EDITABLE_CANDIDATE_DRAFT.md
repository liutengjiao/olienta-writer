# 可编辑候选稿 v0.1

本轮将 AI 候选稿改为可编辑。

## 新行为

1. AI 生成整章后，内容进入“候选稿（未进入正文）”。
2. 候选稿不会自动覆盖正式正文。
3. 作者可以在候选稿区域逐字修改。
4. 修改候选稿时，系统会重新执行规则型冲突检查。
5. 作者点击“采用为正文”后，当前候选稿内容才写入正式正文。
6. 写入正文后，触发自动保存和事实抽取。

## 设计意义

这一步把“作者确认最大”落实到候选稿层：

- AI 只能给草稿。
- 作者可以改每一个字。
- 采用时才进入正式文本。
- 采用后的文本成为后续 AI 必须尊重的确认内容。

## 当前限制

- 候选稿只有一个版本。
- 清空后不可恢复。
- 还不能把候选稿另存为历史版本。
- 冲突检查仍是规则型，不是语义级。

## 下一步

1. 增加候选稿版本历史。
2. 增加采用方式：替换全文 / 追加到末尾 / 插入光标。
3. 增加语义级冲突检查。
4. 增加更细的候选稿与正文逐字 diff 对比。

## 当前对比能力

草稿箱已提供段落级对比：

- 显示候选稿相对正文新增的段落。
- 显示正文相对候选稿独有的段落。
- 显示共同段落数量和段落差值。
- 段落会先做空白规范化，再按完整段落匹配。

这一步用于采用前快速判断“追加”还是“替换”的风险。后续仍需要补逐字差异、按光标插入和更细的改写标记。
