# 本地 Markdown 文件视图

“本地文件”页面用于满足作者可以直接看到 `.md` 文件的要求。

## 当前能力

- 扫描当前项目目录内的 `.md` 文件。
- 同时支持预览项目内的 `.json`、`.jsonl`、`.txt` 文本文件，用于任务、日志、配置摘要等模块。
- 按框架文件、章节蓝图、正文文件、事实库、时间轴、Skill、其它分类。
- 可以在软件内预览 Markdown 原文。
- 事实库约束文件可以在知识库模块内直接编辑保存。
- 文件读取限制在当前项目目录内，避免误读项目外文件。

## 为什么第一版不做任意文件编辑

正文、蓝图和框架文件有自己的保存链路：

- 正文保存后会自动抽取事实，并更新作者确认账本。
- 蓝图保存后会覆盖后续蓝图，并保留历史版本。
- 框架文件保存后会成为 AI 后续生成的硬约束。
- 事实库约束文件本身就是作者可修订的约束，允许在知识库模块保存；保存后会进入后续任务书。

因此第一版“本地文件”页主要负责查看。正文、蓝图和故事构架仍回到对应模块正式编辑，确保核心规则不会被绕过。

## 作者确认文件

`facts/author-confirmation.md` 会显示在事实库分类中。它由保存正文和重新扫描事实时自动刷新，用来让作者直接看到哪些正文已经被确认，AI 后续不得违背。

## 蓝图历史文件

`blueprints/history/last-cascade.md` 会显示最近一次蓝图覆盖记录。每章被覆盖前的旧蓝图会保存到 `blueprints/history/{章节号}/vXXX.md`。

## 任务与日志文本

以下文件也会出现在本地文件索引里：

- `tasks/current.json`
- `tasks/history.jsonl`
- `logs/system-events.jsonl`
- `logs/model-calls/history.md`
- `logs/model-calls/README.md`

它们用于桌面软件内部的任务、日志和模型调用页面。除 Markdown 辅助文档外，JSON/JSONL 文件第一版只预览，不在通用文档页直接编辑。
