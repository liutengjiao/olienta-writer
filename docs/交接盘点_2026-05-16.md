# Olienta 交接盘点

日期：2026-05-16

## 项目定位

Olienta 是本地优先的长篇小说写作桌面软件。当前实现采用 React + TypeScript + Vite 前端和 Tauri/Rust 后端。核心原则是：项目内容落在用户自己的本地目录里，正文、蓝图、事实库、任务书、候选稿和日志都能作为普通 Markdown/JSON 文件查看；AI 只能产出候选内容，作者确认后才进入正式正文。

## 当前验证入口

- 工作目录：`D:\windsurf\olienta`
- 应用目录：`D:\windsurf\olienta\app`
- 完整验证：`cd app && npm run verify`
- 快速前端验证：`cd app && npm run build && npm run lint && npm run smoke:logic`
- 桌面开发：`cd app && npm run desktop:dev`

## 已完成的主要功能

- 项目管理：创建项目、打开本地项目、最近项目、项目结构修复、外部作品目录导入。
- 本地项目模型：标准目录、章节正文、章节蓝图、作者输入、故事框架、事实库、时间线、Skill、候选稿、导出和日志。
- 章节工作流：章节列表、正文编辑、蓝图编辑、作者输入、写作任务书、候选稿生成、候选稿保存、候选稿历史、采用候选稿到正文。
- 作者确认链路：正文保存后写入作者确认记录、系统事件、事实库重扫。
- AI Provider：项目级 Provider JSON、结构化 Provider 管理、用途映射、启用/禁用、运行参数、OpenAI-compatible `/chat/completions` 调用、连接测试。
- AI 草稿：章节候选稿、章节蓝图草案、故事框架草案均已接入 Provider 路由；Provider 不可用时回落本地占位草案。
- 模型调用记录：记录 Provider、任务、章节、输入输出路径、耗时、Token 用量和结果说明；页面已有摘要和筛选列表。
- 知识库：本地 Markdown 扫描、文件预览、全文检索、批量钉选材料、钉选材料进入任务书、外部资料导入。
- Skill：导入、启用/停用、临时启用、基础分类和关键词冲突提示。
- 角色模块：角色文件、角色摘要、角色卡抽取入口和展示骨架。
- 导出：全书、当前章、选中章节的 Markdown/TXT/DOCX 第一版导出。
- 编辑器：通用 Markdown 编辑器、预览、快捷工具栏、快捷键、粘贴清洗、段落/字数统计。
- 界面结构：左侧项目树、模块页、右侧本章助手、纯写作模式、工具与设置分组。
- 测试与质量：`npm run verify` 串联文案检查、构建、lint、逻辑 smoke、dev server smoke、工作流 smoke 和 Rust 测试。

## 未完成或仍偏第一版的功能

- Markdown 编辑器还不是完整 Obsidian 式所见即所得内核。
- 事实抽取主要是规则骨架，准确度和结构化程度还需要加强。
- Skill 冲突仍是关键词规则，缺少更可靠的结构化规则和适用范围分析。
- 角色模块仍需把角色卡、关系网、成长线做成可编辑的完整工作流。
- 时间线 Pro 已有文件和设置基础，但冲突检查、里程碑和付费解锁仍未形成完整产品闭环。
- Word 导出有基础 OpenXML 文档，缺少模板、页眉页脚、章节样式和排版配置。
- 模型调用记录还没有费用估算、重试链路、Prompt 摘要和失败聚合诊断。
- AI 生成还不是流式输出；前端已有取消/忽略过期结果保护，但后端请求级取消和重试策略仍可加强。
- Provider 配置没有独立的密钥迁移、批量测试、成本参数和模型能力预设。
- 项目健康检查已有骨架，后续可以增加一键修复的可视化结果和风险说明。

## 建议接手路线

1. 先保持 `npm run verify` 绿灯，不要跳过 smoke 和 Rust 测试。
2. 优先补齐“能让作者每天使用”的链路：正文编辑、候选稿对比、模型调用诊断、导出。
3. 第二优先级推进知识库和事实库：检索质量、钉选材料管理、事实抽取准确度。
4. 第三优先级推进商业化模块：时间线 Pro、Word 模板、Provider 成本统计。
5. 所有 AI 输出继续遵守“候选优先，作者确认后入正文”的产品边界。

## 下一个大模块建议

- 模型调用诊断：筛选列表、失败聚合、费用估算、Provider 成本配置。
- 候选稿对比增强：按光标插入、逐字差异定位、保留正文已有段落。
- Word 导出模板：标题样式、分页、页眉页脚、章节目录。
- 事实库增强：从正文抽取角色/地点/时间/事件，支持手动确认和禁止违背规则联动。
- 角色模块闭环：角色卡编辑、关系图、成长线按章节追踪。

## 给下一个工具的注意事项

- 不要把 `.olienta/ai-providers.json` 的 API Key 写进日志或文档。
- 不要让 AI 直接覆盖正式正文，除非作者点击采用或保存。
- 不要绕开项目路径安全检查写入任意路径。
- 不要把“本地 Markdown”页变成任意编辑入口，正式编辑仍应回到对应模块。
- 修改前先看 `docs/当前进度_2026-05-15_接手推进总控.md` 和最近的 `docs/当前进度_2026-05-16_*.md`。
