## 已完成：基础项目形态

1. 项目采用本地文件优先模型，不把正文、蓝图、事实、Skill 藏进数据库。
2. 新建项目会补齐 `manuscript/`、`blueprints/`、`framework/`、`facts/`、`characters/`、`timeline/`、`skills/`、`tasks/`、`logs/`、`models/` 等目录。
3. 左侧框架栏已经按“首页、项目结构、知识库、角色、任务、日志、模型调用”等模块逻辑展开。
4. 项目结构下的核心栏目遵循：
   - 小说设置
   - 故事构架
   - 章节蓝图
   - 草稿箱
   - 正文

## 已完成：章节写作链路

1. 每章可以保存作者输入。
2. 每章可以装配写作任务书：

```text
tasks/writing-briefs/{章节号}.md
```

3. 任务书会读取当前章蓝图、作者输入、故事构架、事实库、作者确认记录、未闭合伏笔、Skill、写作方法配置。
4. AI 只能生成候选稿，候选稿默认保存到：

```text
manuscript/candidates/{章节号}.md
```

5. 候选稿审查报告保存到：

```text
manuscript/candidates/reviews/{章节号}.md
```

## 已完成：作者确认链

1. 候选稿采用为正文后，会写入 `logs/confirmations/{章节号}.md`。
2. `candidate_adopted` 系统事件会记录确认摘要路径。
3. 历史任务会记录 `candidate_confirmation_summary_written`。
4. 正文保存后，内容进入作者确认链，后续 AI 必须尊重。

## 已完成：事实库

1. 正文保存后会自动抽取事实。
2. 事实写入 `facts/confirmed-facts.md` 和分类事实文件。
3. 候选稿审查会读取已确认事实、禁止违背规则、未闭合伏笔。
4. 审查只提醒，不拦截作者采用。

## 已完成：角色模块

1. 可以从 `framework/03-characters.md` 抽取结构化角色卡。
2. 生成文件包括：

```text
characters/cards/INDEX.md
characters/cards/*.md
characters/relations.md
characters/growth.md
```

3. 写作任务书会读取角色模块资料。
4. 候选稿审查会读取角色卡、关系图谱、成长线。
5. 如果候选稿提到角色却不承接角色卡边界，会给出“角色提醒”。
6. 如果候选稿含否定表达并触碰角色卡边界，会给出“角色风险”。

## 已完成：时间轴及里程碑进入写作约束链路

1. 写作任务书新增“时间轴及里程碑”部分。
2. 免费锁定态或未开启冲突检查时，任务书只写入 Timeline Pro 锁定说明，不注入具体时间轴内容。
3. 当 `.olienta/timeline-settings.json` 中 `enabled=true` 且 `conflictCheck=true` 时，任务书会读取：

```text
timeline/events.md
timeline/milestones.md
```

4. 候选稿审查新增“时间轴高危”提醒，检查当前章是否提前触发未来章节里程碑、真相、高潮、终局或伏笔回收。
5. 候选稿审查报告的审查范围已补充“时间轴及里程碑”。
6. 新增后端测试：
   - `timeline_context_enters_brief_only_when_pro_conflict_check_is_enabled`
   - `candidate_review_reads_timeline_milestone_boundaries_when_enabled`
