# 当前进度：定位项目文件

日期：2026-05-14

## 本步目标

Olienta 的作品项目是外置的本地文件夹，正文、蓝图、草稿、事实库、Skill 和配置文件都应当能被作者直接看到、打开、备份，也可以被 Obsidian 一类工具读取。

因此，本步补上“定位具体文件”的能力：作者在软件内看到某个 `.md`、`.txt`、`.json` 等项目文件时，可以一键让系统文件管理器定位到它，而不是只能打开整个项目根目录。

## 已完成

1. 后端新增 `reveal_project_path`
   - 只允许定位当前项目根目录下的文件或文件夹。
   - 拒绝 `../` 这类越界路径。
   - 拒绝把 Olienta 软件目录本身当成作品项目目录。
   - 文件不存在时给出明确错误。
   - Windows 下使用资源管理器选中具体文件，macOS 下使用 Finder 显示文件，Linux 下打开父级目录。

2. 前端新增文件定位入口
   - 项目首页的“外部作品文件夹地图”里，每个文件旁边有“定位”。
   - 本地 Markdown 文件浏览器里，每个文件旁边有“定位”。
   - 当前预览文件的操作区增加“定位当前文件”。

3. 浏览器预览保护
   - 如果不是桌面端，而是在浏览器预览模式下点击定位，不会假装能打开系统文件管理器。
   - 页面会提示：浏览器预览不能定位系统文件，桌面端会定位对应路径。

4. 自动测试
   - 新增测试覆盖合法文件定位、越界路径拒绝、缺失文件拒绝。
   - 后端测试全部通过。
   - 前端检查和生产打包通过。

## 为什么这样做

这一步继续落实“项目内容不属于软件私有数据”的原则。Olienta 负责组织、生成、校验和辅助写作，但作者的作品文件仍然是作者可以直接接触的普通文件。

这种设计方便：

- 作者直接用文件管理器查看项目结构。
- 用 Obsidian 或其他 Markdown 工具打开同一批文件。
- 手动备份、同步、迁移项目。
- 排查 AI 生成或保存后的具体文件变化。
